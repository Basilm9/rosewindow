### 2. Implementation Instructions
```js
// scripts/lib/statechartToMermaid.mjs
/** @param {import('xstate').AnyStateMachine} machine  @returns {string} Mermaid stateDiagram-v2 text */
export function statechartToMermaid(machine) { … }
```
Walk `machine.root` recursively in definition order (`Object.values(node.states)`):
- `[*] --> <initial>` for each compound node (`node.initial.target[0].key`); `final` nodes get `<key> --> [*]`.
- Compound nodes become `state round { … }`; a `history` node `round.hist` becomes `state "H*" as round_hist` inside `round`.
- For each `[eventType, transitions]` of `node.transitions` (skip internal events `xstate.*`) and each `node.always` entry: one line `src --> tgt : EVENT [guard] / action1, action2`; eventless lines omit `EVENT`; a targetless (self/fallback) transition is drawn as `src --> src`. Guard name = `typeof t.guard === 'string' ? t.guard : t.guard?.type`; action names = `t.actions.map(a => typeof a === 'string' ? a : a.type)` with `xstate.assign` shown as `assign`. (Checked on XState 5.32.6: guards and actions named in `setup()` stay **strings** in `node.transitions`, `node.always` and `node.entry`; only an inline `assign(…)` is a function, with `type` `'xstate.assign'`. Reading `.type` alone would drop every guard and action name.)
- Mermaid identifier = the node's path below the root joined by `_` (`setup`, `round`, `round_draft`, `round_hist`, `paused`), declared once as `state "<key>" as <identifier>` so the box shows the plain key; entry actions as a `note right of <id> : entry / forfeitRound`.
- Deterministic: no timestamps; arrays kept in definition order; final string ends with `\n`.

CLI `scripts/generate-statecharts.mjs`: create a Vite server in middleware mode (`createServer({ server: { middlewareMode: true }, appType: 'custom', logLevel: 'silent' })`), `ssrLoadModule('/src/controller/index.ts')`, take `gameStatechart` and `beamStatechart`, write the two `.mmd` files and `docs/statecharts.md` (header "Generated by scripts/generate-statecharts.mjs. Do not edit by hand.", one section per machine with a short legend: `[guard]`, `/ action`, `H*` = deep history), only if content changed, then `server.close()`. Print `Statecharts updated: 2 diagrams (N states, M transitions)`.

**Tests** `tests/architecture/statecharts.test.ts` (import the machines directly; Vitest resolves aliases) — criterion: one assertion per state and per section 6 transition family:
